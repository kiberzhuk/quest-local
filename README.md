# Quest Local

Программа для Windows, которая подключает Quest 3 к ADB по Wi-Fi и открывает
обычные настройки Android в шлеме. В том числе раздел «Для разработчиков».


Подключение начинается по Bluetooth. Для авторизации используется ваш вход
Meta в Vivaldi, затем работа идёт через ADB. Интерфейс на русском языке.

## Что понадобится

- Windows и Python 3.11 или новее с Tkinter.
- Bluetooth на компьютере.
- Браузер Vivaldi с выполненным входом в Meta.
- [Android SDK Platform-Tools](https://developer.android.com/tools/releases/platform-tools).
  Добавьте папку с `adb.exe` в PATH. Программа также ищет его в
  `%PROGRAMFILES%\platform-tools` и `%LOCALAPPDATA%\Android\Sdk\platform-tools`.
- Компьютер и Quest в одной локальной сети.

## Запуск

1. [Скачайте архив](https://github.com/kiberzhuk/quest-local/releases/latest)
   и распакуйте его. Один раз запустите `setup.bat`: он создаст `.venv`
   и установит зависимости. Для последующих запусков используйте `start.bat`.
2. Нажмите «Установить расширение». Откроются страница расширений Vivaldi
   и папка проекта. Включите режим разработчика расширений, нажмите
   «Загрузить распакованное расширение» и выберите `vivaldi-extension`.
   Это настройка браузера, не шлема.
3. Нажмите «Войти в Meta», а в открытой вкладке «Использовать вход Meta».
   Если расширение только что установлено, обновите вкладку.
   Закрывать Vivaldi не нужно.
4. Разбудите и разблокируйте Quest. Нажмите «Найти Quest», выберите свой шлем
   и нажмите «Подключиться».
5. Нажмите «Подключить Wi-Fi ADB». Подтвердите запросы в программе и в шлеме.
   Разрешение отладки для текущей Wi-Fi-сети может появиться отдельно от сопряжения
   с компьютером. Порт подключения иногда появляется с задержкой; программа
   ждёт его до двух минут.
6. Когда подключение ADB подтвердится, нажмите «Открыть „Для разработчиков“».
   В шлеме появится окно Android с переключателем режима разработчика.

Между этими действиями повторный вход Meta не нужен. После закрытия программы
секрет придётся получить заново, но сохранённый вход в Vivaldi останется.

## Остальные кнопки

«Открыть „Сеть и интернет“» открывает сетевые настройки Android.
Кнопки открытия разделов сами ничего не переключают.

«Включить отладку для SideQuest» включает Android-настройки разработчика
и USB-отладку, затем читает их повторно. Это отдельное действие с подтверждением.
Программа не устанавливает APK.

«Не усыплять снятый шлем» позволяет снять Quest, не прерывая работу.
После этого он расходует больше энергии и греется. Не оставляйте его без
присмотра. Когда закончите, нажмите «Вернуть обычный сон»: закрытие программы
само по себе сон не возвращает.

«Проверить статус» читает сведения по Bluetooth, «Проверить ADB» проверяет
доступ к оболочке и настройки отладки. Журнал можно скопировать кнопкой в окне.

## Если настройки не открылись

Сначала проверьте, что шлем разблокирован и разрешил отладку для этой сети.
Если открыт диалог Guardian, подтвердите безопасную границу в шлеме и нажмите
кнопку открытия ещё раз. Пока этот диалог показан, Quest откладывает запуск окон.

После перезагрузки или смены сети может понадобиться снова нажать
«Подключить Wi-Fi ADB». Порт меняется; программа ищет его только по IP выбранного
шлема. Сканирования сети нет.

Главная страница Android Settings на проверенной прошивке закрыта для внешнего
запуска, поэтому программа открывает разделы напрямую. Если нужный раздел
недоступен на другой прошивке, она сообщит об ошибке, не меняя разрешения
системных компонентов.

## На чём проверено

Для входа в Meta и подключения шлема я использовал браузер
[Vivaldi](https://vivaldi.com/). С другими браузерами этот способ не проверял.

Quest 3 с V2.10, сборка `53145330026600520`. Работают Wi-Fi ADB, разделы
«Для разработчиков» и «Сеть и интернет». Окна проверены в самом шлеме;
переключатель Android-режима разработчика был включён. Отдельно проверены
установка тестового APK и запись файла в `Movies` через ADB.
Подключение по USB и работа SideQuest по кабелю не проверялись.

Android-режим разработчика и статус разработчика в аккаунте Meta отличаются.
Программа открывает Android-настройки, но не регистрирует аккаунт разработчика
Meta. На тестовом шлеме общий Bluetooth-статус Developer Mode показывал `0`
даже при включённом переключателе и работающем ADB.

После перезагрузки прямой статус отладки сохранился, а Wi-Fi ADB подключился
после восстановления соединения. На других моделях и прошивках поведение
может отличаться. Проект не связан с Meta.

## Данные и доступ

Локальное расширение Vivaldi получает токен Meta только после нажатия кнопки.
Программа запрашивает `device_secret` напрямую у `graph.oculus.com`, держит
его в памяти и не записывает в файлы или журнал. Браузер хранит свою сессию
как обычно. Пароль Meta вводится только на сайте Meta.

Сопряжение сохраняется в стандартном хранилище ключей ADB. Закрытие программы
и отмена операции не удаляют его и не отключают отладку в шлеме. Используйте
свою сеть, а ненужные разрешения отзывайте в настройках Quest.

Программа не проверяет цепочку сертификата Meta при BLE-подключении.
Выбирайте свой шлем рядом с компьютером. Перед отправкой журнала уберите
личные сведения, включая IP и имена устройств. Подробности в [SECURITY.md](SECURITY.md).

## Для разработки

```powershell
python -m pip install -r requirements.txt
python -m unittest discover -s tests -v
python app.py --smoke-test
```

Тесты работают без шлема и аккаунта Meta. GitHub Actions запускает их на Windows
с Python 3.11 и 3.12.

`python export_source.py` собирает архив в `exports/`. В него входят только
исходники из заданного списка. Окружение Python, APK, ключи и диагностические
файлы не включаются.

Описание Bluetooth-протокола взято из
[quest-ble-client](https://github.com/ptrpaws/quest-ble-client/blob/main/PROTOCOL.md)
и его [схемы полей](https://github.com/ptrpaws/quest-ble-client/blob/main/protocol.proto).
Системные APK в репозиторий не входят.
