# Quest Local

Локальная утилита для **Windows / Python 3.11+**: подключение Meta Quest 3 к Wi-Fi ADB
через Bluetooth и открытие обычного Android-раздела **«Для разработчиков»**.
Не требует предварительной установки APK в шлем.

Версия **0.5.0**. Независимый проект, не продукт Meta. Совместимость с другими
моделями и прошивками не гарантируется.

## Что проверено на настоящем шлеме

Quest 3, V2.10, incremental `53145330026600520`:

- вход через обычный профиль Vivaldi, авторизация владельца по BLE;
- сопряжение и доступ Wi-Fi ADB shell;
- открытие Android Settings → **«Для разработчиков»** и **«Сеть и интернет»**;
- пользователь подтвердил появление окна; Android-переключатель «Режим разработчика»
  на экране был включён;
- установка/запуск отдельного тестового APK и запись файла в `Movies` при ручной
  проверке. Программа сама APK не устанавливает, фильмы не копирует;
- после перезагрузки прямой BLE-статус `6002` сохранился равным `1`;
  Wi-Fi ADB потребовал восстановления и позднее снова подключился.

**Это не регистрация аккаунта разработчика Meta.** Обработчик `6002` на проверенной
сборке читает Android `adb_enabled`. Общий флаг BLE `8001/61` оставался `0` даже
при работающей отладке и включённом Android-переключателе. Команда Quest `6001`
получила `NOT_DEVELOPER` (`code_v2=1054`). Программа не подменяет эти показания
и не обходит проверку аккаунта. USB-подключение и сам SideQuest по кабелю не проверены.

## Требования

- Windows, Python 3.11+ с Tkinter, Bluetooth на ПК.
- [Android SDK Platform-Tools](https://developer.android.com/tools/releases/platform-tools):
  `adb.exe` в PATH, `%PROGRAMFILES%\platform-tools` либо
  `%LOCALAPPDATA%\Android\Sdk\platform-tools`.
- Установленный Vivaldi с вашим входом Meta и локальным расширением из этого проекта.
- ПК и Quest в одной доверенной локальной сети; шлем включён и разблокирован.

## Быстрый запуск

1. Скачайте исходники в отдельную папку. Запустите **`setup.bat`** — создаётся
   локальная `.venv`, зависимости устанавливаются с PyPI.
2. Запустите **`start.bat`**.
3. Один раз нажмите **«Установить расширение»**. В Vivaldi включите режим
   разработчика расширений → «Загрузить распакованное расширение» → выберите
   папку **`vivaldi-extension`**. Это режим расширений браузера, не режим шлема.
4. Нажмите **«Войти в Meta»**, затем **«Использовать вход Meta»** в открытой вкладке.
   При необходимости войдите на официальном сайте Meta. После установки расширения
   обновите локальную вкладку. Vivaldi закрывать не нужно.
5. **«Найти Quest»** → выберите свой шлем → **«Подключиться»**.
6. **«Подключить Wi-Fi ADB»** → подтвердите действие и запросы отладки в шлеме.
   **Сопряжение ПК и разрешение отладки в текущей Wi-Fi-сети — разные шаги.**
   Отдельный порт подключения может появиться позднее; программа ждёт до двух минут.
7. После строки **«ПОДТВЕРЖДЕНО: беспроводной ADB shell»** нажмите
   **«Открыть „Для разработчиков“»**. Проверьте окно и переключатели в шлеме.

Вход Meta повторять между кнопками не нужно: секрет хранится в памяти до закрытия
программы. После её закрытия получите секрет заново. При потере BLE-сессии снова
подключитесь; уже выполненное сопряжение ПК сохраняется в стандартном хранилище ADB.

## Кнопки программы

| Кнопка | Действие |
| --- | --- |
| Проверить статус | Читает BLE-статусы; не включает режим. При авторизации отдельно показывает `6002`. |
| Подключить Wi-Fi ADB | Читает IP выбранного Quest по BLE; сопрягает и подключает только этот IP. |
| Проверить ADB | Проверяет shell и читает три Android-флага отладки. |
| Открыть «Для разработчиков» | Стандартный Intent `android.settings.APPLICATION_DEVELOPMENT_SETTINGS`, только пакет `com.android.settings`. |
| Открыть «Сеть и интернет» | Стандартный Intent `android.settings.WIRELESS_SETTINGS`, тот же пакет. |
| Включить отладку для SideQuest | С подтверждением записывает `development_settings_enabled=1`, `adb_enabled=1` и читает их повторно. Не меняет статус аккаунта Meta. |
| Не усыплять снятый шлем | С подтверждением включает виртуальный датчик надетого Quest, проверяет состояние и wake lock. |
| Вернуть обычный сон | Возвращает физический датчик и проверяет результат. |
| Скопировать журнал | Копирует рабочий журнал в буфер обмена; автоматически на диск он не сохраняется. |

Кнопки открытия настроек **не меняют переключатели, сон или разрешения компонентов**.
Вместо недоступной главной Activity используются проверенные экспортированные
разделы. Если разрешение Intent ведёт к неизвестной/отключённой Activity, запуск
останавливается без перебора компонентов. Успех требует **одной и той же Activity
в состоянии `RESUMED` и `mVisible=true`**, а не только положительного ответа запуска.
Окончательное подтверждение видимой VR-панели — за пользователем.

## Если окно не появляется

- Разбудите и разблокируйте шлем. Проверьте разрешение беспроводной отладки
  **для текущей сети**, даже если сопряжение уже прошло.
- Если открыт диалог **Guardian**, безопасно подтвердите границу в шлеме,
  затем нажмите кнопку открытия ещё раз. Quest может поставить запуск в очередь.
  Программа не отключает защитную границу.
- Главная Activity Android Settings на проверенной сборке не экспортирована;
  её прямой запуск запрещён. Кнопка «Для разработчиков» открывает нужный раздел напрямую.
- После перезагрузки/смены сети порт ADB может измениться. Повторите подключение.
  Для уже выбранного IP программа обнаруживает новый порт через mDNS;
  другие устройства сети не выбирает и порты не сканирует.
- Ошибки прошивки/Meta выводятся в журнал, без обещания обхода. Если нет данных
  сопряжения или разрешения, вход по Wi-Fi не считается подтверждённым.

## Сон и изменения состояния

Во время первичного сопряжения BLE-таймер сна временно увеличивается до 900 секунд,
затем восстанавливается при завершении/ошибке/отмене, если BLE-связь сохранилась.
Ошибка восстановления отображается. Это не бессрочное удержание бодрствования.

«Не усыплять снятый шлем» использует фиксированную команду
`com.oculus.vrpowermanager.prox_close`; возврат — `automation_disable`.
**Закрытие программы не отменяет эту настройку.** После работы верните обычный сон:
удержание бодрствования увеличивает нагрев и расход энергии. Не оставляйте шлем
без присмотра. После перезагрузки проверьте состояние заново.

Отмена операции не откатывает уже применённые изменения и не удаляет сопряжение.
Закрытие программы не отключает беспроводную отладку. Отозвать ПК/отладку можно
в настройках шлема. Не используйте её в недоверенной сети.

## Данные и безопасность

- Нет облачного сервера проекта, телеметрии, загрузки чужого JavaScript,
  чтения баз паролей/cookies, завершения браузера или снятия блокировок профиля.
- Расширение получает только `oc_www_at` для `https://secure.oculus.com/` по явному
  нажатию. Передача — временному localhost-серверу на `127.0.0.1` со случайным
  одноразовым адресом, проверкой Host/Origin и ограничением размера; без CORS.
- С токеном выполняется прямой HTTPS-запрос только к `graph.oculus.com`.
  Перенаправления и системные HTTP-прокси для этого запроса отключены.
- Токен/секрет не сохраняются программой в файлы, журнал или аргументы команд.
  Vivaldi самостоятельно хранит свою обычную сессию. Защищённое стирание памяти
  не гарантируется. Код сопряжения передаётся ADB через stdin и скрывается в ответе.
- BLE использует HMAC и NaCl Box. Подпись проверяется присланным сертификатом,
  но цепочка Meta и заранее доверенный отпечаток не проверяются. Выбирайте свой шлем.
- GUI не предоставляет произвольную консоль ADB, удаление приложений, сброс,
  перепрошивку или изменение аккаунтов.

Подробнее: [SECURITY.md](SECURITY.md). Перед отправкой журнала удалите персональные
сведения: IP, имена устройств и другие идентификаторы.

## Проверка исходников

```powershell
python -m pip install -r requirements.txt
python -m unittest discover -s tests -v
python app.py --smoke-test
```

Тесты выполняются без шлема/аккаунта и не обращаются к Meta. Они проверяют протокол,
шифрование, обработку отказов, сопряжение с отдельными портами и проверку окна.
Это не гарантия совместимости с каждой прошивкой. Windows CI настроен для Python 3.11/3.12.

## Подготовка к GitHub

Корень публикуемого проекта — **эта папка `quest-local`**, не родительская рабочая папка.
Для чистого архива:

```powershell
.\.venv\Scripts\python.exe export_source.py
```

Архив появится в `exports/QuestLocal-0.5.0-source.zip`. Файлы выбираются по явному
списку: код, расширение, инструкции, тесты и CI. В архив **не входят** `.venv`, кэши,
APK, ключи, дампы, старое тестовое приложение или локальные диагностические файлы.
Архив содержит проект сразу в корне — распакуйте его в отдельную папку для Git.
Проверьте состав и исходники перед публикацией. `.gitignore` также исключает локальные
артефакты, но не защищает файлы, уже добавленные в Git: всегда просматривайте `git diff --cached`.

Авторизация GitHub не связана с авторизацией Meta. Никогда не добавляйте пароли,
токены и приватные ключи в исходники, issues или команды. Для GitHub используйте
вход через браузер/`gh auth login`. Лицензия проекта — [MIT](LICENSE).
